# Implementations disagree whether a deactivated did:webvh DID keeps its implicit services
kind: todo
created: 2026-09-15T23:15Z

- 2026-09-15T23:16Z Found by tests/test_conformance.py against DIF's vectors. For the deactivate case, java records a resolved document with no service block at all, while ts, dart, rust, java-eecc and python all keep the implicit #files and #whois. We follow the majority: the specification defines those services for a did:webvh DID and carves out no exception for deactivation.

Recorded as KNOWN_DIVERGENCES[('deactivate','java')] in the conformance module rather than tolerated silently, so it stays visible and a reviewer can disagree with the call.

Worth raising with DIF: the suite has a vector for this and five of six implementations agree, so pinning it costs them little and removes an interop question. A resolver that drops services on deactivation and one that keeps them will disagree about whether a deactivated DID still advertises a whois endpoint. DIF repos carry no posting restriction, so this is postable as a plain issue whenever Daniel wants it posted.
